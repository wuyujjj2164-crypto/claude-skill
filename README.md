# Claude Code Prompt Architecture Skill

> 从 Claude Code 源码中提炼的、经过工业验证的 AI 编程助手系统提示词架构模板

## 这是什么？

本项目提供一套**模块化、参数化、去品牌化**的系统提示词架构模板，提炼自 Claude Code CLI 的真实源码。无论你是在构建自己的 AI 编程助手、优化现有提示词、还是学习提示词工程的最佳实践，都可以直接使用或参考这套架构。

核心价值：

- **工业验证** — 每一条规则都来自生产环境，经过数百万用户的使用验证
- **模块化设计** — 11 个独立模块，按需组合，适配不同场景
- **参数化模板** — 16 个占位符变量，一键适配 Open Code、Cursor、Continue 等不同平台
- **缓存策略** — 静态/动态分离的缓存设计，节省 60-70% 的 token 成本

## 架构总览

Claude Code 的系统提示词采用 5 层组装管线：

```
用户输入: "帮我修个 bug"
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Layer 1: 身份前缀 (Identity Prefix)                      │
│  → 声明 AI 助手的身份和角色                                │
└──────────────────────┬───────────────────────────────────┘
                       │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Layer 2: 核心系统提示词 (Core System Prompt)              │
│  ┌────────────────────────────────────────┐               │
│  │ 静态区 (可跨用户缓存)                    │               │
│  │  - 安全指令 / 系统规则 / 任务执行指南     │               │
│  │  - 谨慎行动 / 工具使用 / 语气风格        │               │
│  ├────────────────────────────────────────┤               │
│  │ ★ 缓存边界 (Cache Boundary) ★           │               │
│  ├────────────────────────────────────────┤               │
│  │ 动态区 (每轮可能变化)                    │               │
│  │  - 环境信息 / 会话指引 / MCP 指令        │               │
│  └────────────────────────────────────────┘               │
└──────────────────────┬───────────────────────────────────┘
                       │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Layer 3: 工具描述 (Tool Descriptions)                     │
│  → 各工具的独立定义，作为 API 请求的 tools[] 数组发送       │
└──────────────────────┬───────────────────────────────────┘
                       │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Layer 4: 附件注入 (Attachments)                           │
│  → @文件引用、项目规则、IDE 诊断等，渲染为 <system-reminder> │
└──────────────────────┬───────────────────────────────────┘
                       │
    ▼
┌──────────────────────────────────────────────────────────┐
│  Layer 5: 最终组装 (Final Assembly)                        │
│  → system[] + tools[] + messages[] → API 请求             │
└──────────────────────────────────────────────────────────┘
```

## 11 个模块

| # | 模块 | 用途 | 必选 |
|---|------|------|------|
| 1 | 身份前缀 | 声明 AI 助手的身份和角色 | ✅ |
| 2 | 安全指令 | 划定安全边界，防止滥用 | ✅ |
| 3 | 系统规则 | 输出格式、权限模式、上下文管理 | ✅ |
| 4 | 任务执行指南 | 核心行为准则——"不多不少，恰好完成" | ✅ |
| 5 | 谨慎行动原则 | 可逆操作自由执行，不可逆操作必须确认 | ✅ |
| 6 | 工具使用偏好 | 专用工具优先，并行调用独立工具 | 推荐 |
| 7 | 语气与风格 | 专业简洁，无 emoji，代码引用格式 | 推荐 |
| 8 | 输出效率 | 简洁模式 / 详细散文模式 | 推荐 |
| 9 | 环境信息 | 工作目录、操作系统、Shell、模型版本 | 推荐 |
| 10 | 子代理提示 | 子任务委派时的独立提示词 | 可选 |
| 11 | 自主模式 | 无人值守时的行为准则 | 可选 |

## 快速开始

### 1. 选择模块组合

根据场景选择需要的模块：

| 场景 | 必选 | 推荐 | 可选 |
|------|------|------|------|
| CLI 编程助手 | 1-5 | 6,7,8A,9 | 10,11 |
| IDE 集成助手 | 1-5 | 6,7,8B,9 | 10 |
| 代码审查机器人 | 1-5 | 7,8A | - |
| 自主编程代理 | 1-4 | 6,7,8A,9 | 10,11 |
| 子代理/子任务 | 10 | 9 | - |

### 2. 替换占位符

将模板中的占位符替换为你的平台实际值：

| 占位符 | 含义 | Open Code 示例 |
|--------|------|----------------|
| `{AGENT_NAME}` | 助手名称 | `Open Code` |
| `{ORG}` | 组织名 | `YourOrg` |
| `{MODEL_FAMILY}` | 模型家族名 | `GPT` |
| `{READ_TOOL}` | 文件读取工具名 | `read_file` |
| `{EDIT_TOOL}` | 文件编辑工具名 | `edit_file` |
| `{BASH_TOOL}` | Shell 执行工具名 | `shell` |
| `{PROJECT_RULES_FILE}` | 项目规则文件名 | `AGENT.md` |

完整占位符列表见 [SKILL.md](.trae/skills/claude-code-prompt-arch/SKILL.md)。

### 3. 按顺序组装

模块必须按编号顺序拼接——顺序影响模型的注意力权重。身份前缀最先出现权重最高，安全指令紧随其后。

### 4. 实施缓存策略

将模块 1-8 标记为静态区（可全局缓存），模块 9+ 标记为动态区（不缓存或按组织缓存）。在静态区和动态区之间插入缓存边界标记。

## 缓存策略：为什么静态/动态分离很重要

这是 Claude Code 提示词架构中最关键的设计：

- **静态区**（模块 1-8）：所有用户/会话共享，可使用全局缓存，用户 A 的缓存可被用户 B 复用
- **缓存边界**：一个特殊标记，分隔静态区和动态区
- **动态区**（模块 9+）：每轮可能变化，不可全局缓存

这种设计让约 60-70% 的提示词内容可以跨用户复用，大幅节省 token 成本。

## 作为 Trae Skill 使用

如果你使用 Trae IDE，本仓库已包含可直接加载的 Skill：

1. 将 `.trae/skills/claude-code-prompt-arch/` 目录放入你的 Trae 项目
2. 在对话中提及"系统提示词"或"提示词架构"即可激活 Skill
3. Skill 会引导你选择模块、适配参数、组装完整提示词

## 适配其他平台

### Open Code

替换工具名映射即可使用：

| Claude Code | Open Code |
|-------------|-----------|
| `Read` | `read_file` |
| `Edit` | `edit_file` |
| `Write` | `write_file` |
| `Bash` | `shell` |
| `Glob` | `find_files` |
| `Grep` | `search` |

### Cursor

Cursor Agent 模式有内置系统提示词，本架构可作为补充增强。

### Continue

Continue 使用 `config.yaml` 配置系统提示词，项目规则使用 `.continuerules` 文件。

## 核心设计哲学

从 Claude Code 源码中提炼出的三条核心哲学：

1. **不多不少，恰好完成** — 不添加未请求的功能，不重构未修改的代码，不创建不必要的抽象
2. **先读后改** — 在理解代码之前不提议修改，在验证之前不声称完成
3. **可逆自由，不可逆谨慎** — 本地可逆操作自由执行，影响他人或不可逆操作必须确认
